1. PROJECT OVERVIEW
================================================================================

A browser-based first-person "VR-like" career simulator built with:
- Three.js r128 (loaded from CDN, no build tools)
- Vanilla HTML/CSS/JavaScript (no frameworks)
- Single-page app that runs by opening index.html

Users choose a profession (Doctor, Engineer, Chemist, Architect, Pilot),
enter a first-person 3D room, look around with the mouse (pointer-lock),
move with WASD, and interact with objects using the E key.

Each room has 8-10 interactable objects with detailed real-world descriptions
displayed in a slide-in info panel. A task system tracks which objects
the player has explored.

3. ARCHITECTURE & MODULE SYSTEM
================================================================================

All JS files use the IIFE (Immediately Invoked Function Expression) pattern
to define globals without polluting the global scope. No ES modules, no
bundlers — everything loaded via <script src="..."> tags.

LOAD ORDER (critical — must stay this way):
  1. roles.js          — defines ROLES array (no dependencies)
  2. controls.js       — defines VRControls (no THREE at top level)
  3. interactions.js   — defines VRInteractions (no THREE at top level)
  4. BloomPostFX.js    — defines BloomPostFX (no THREE at top level)
  5. Particles.js      — defines ParticleSystem (no THREE at top level)
  6. CanvasTextures.js — defines CanvasTextureManager (no THREE at top level)
  7. main.js           — loads Three.js from CDN dynamically, then calls init()

KEY RULE: No file may reference THREE at the top level of its IIFE.
THREE is only available after the CDN script loads (async). All THREE
usage must be inside functions/constructors that are called AFTER init().
This was the main bug encountered twice during development.

MODULE API:
  VRControls:
    init(camera, container)  — call after THREE loads
    enable() / disable()
    update(dt)               — call every frame
    setBounds({minX,maxX,minZ,maxZ})
    requestLock()
    setYaw(v) / setPitch(v)
    setOnFootstep(fn)        — callback for footstep sounds
    getYaw() / getPitch()    — current look angles
    isSprinting() / isCrouching() / isMoving()
    getStamina() / getStaminaMax()
    getBobOffset()           — {x, y} head bob offsets

  VRInteractions:
    init()                   — call after THREE loads
    setInteractables(meshes) — array of Three.js meshes
    clear()
    enable() / disable()
    update(camera)           — call every frame

  VRTasks:
    init(tasks)              — array of {id, label, objectName}
    complete(objectName)     — marks task done, shows notification

  VRSound:
    init() / beep(freq,dur,vol) / interact() / taskDone() / allDone()
    toggle() — returns new on/off state

  Quality:
    detect() / setTier(0-2) / getTier() / cycleTier()
    shadowsEnabled() / bloomEnabled() / particlesEnabled() / screensEnabled()

  BloomPostFX:
    constructor(renderer, scene, camera, opts)
      opts: { threshold, intensity, blurSize, grain, vignette,
              chromAb, exposure }
    render() — replaces renderer.render(scene, camera)
    resize(w, h) / dispose() / enabled property

  ParticleSystem:
    constructor(scene, {preset, count, bounds, origin})
      presets: dust, steam, sparks, firefly, sparkle, smoke, confetti
    update(dt) / dispose() / setVisible(bool)

  CanvasTextureManager:
    constructor()
    create(type, opts) — returns THREE.CanvasTexture
    update()           — call every 3rd frame
    dispose()

4. DETAILED FILE DESCRIPTIONS
================================================================================

--- index.html ---
  Main HTML shell containing:
  - Role selection screen (gradient background, animated cards)
  - Instructions overlay (WASD/Mouse/E/Shift/Space/Esc guide)
  - Pointer lock prompt ("Click to resume")
  - Scene transition overlay (fade-to-black div)
  - HUD: crosshair, role label, task panel, interaction prompt,
    info panel (slide-in), sound toggle, back button, notification toast,
    quality badge, mini instructions
  - Canvas container for Three.js
  - All 7 script tags in dependency order

--- style.css ---
  All UI styling. Key sections:
  1. Reset & base styles
  2. Canvas (fullscreen fixed)
  3. Role selection screen with staggered card entrance animations
     (each card fades+slides in with increasing delay) and parallax
     tilt effect following mouse position
  4. Instructions overlay with fade-in animation
  5. Pointer lock prompt with glow pulse animation
  6. HUD elements:
     - Crosshair with spring-animated state changes (cubic-bezier overshoot)
     - Role label with slide-in
     - Task panel with slide-in, task completion checkmark pops with bounce
     - Interaction prompt with spring fade+slide
     - Info panel with spring slide-in+scale (CSS transition, not animation)
     - Notification toast with bounce-in/bounce-out (scale transform)
  7. Scene transition overlay (opacity fade)
  8. Quality badge (bottom-right, click to cycle)

  CSS animations used:
  - gradientShift (selection screen background)
  - titleShift (rainbow gradient text)
  - cardEnter (staggered card entrance)
  - instrFadeIn (instructions box)
  - lockPulse (pointer lock glow)
  - pulse (click prompt)
  - fadeSlideIn (HUD elements)
  - checkPop (task completion bounce)

--- roles.js ---
  Pure data file defining the ROLES array. Each role object contains:
  {
    id, title, icon, description, accentColor,
    roomColor, floorColor, ceilingColor,
    roomSize: {width, height, depth},
    playerStart: {x, y, z},
    ambientColor, ambientIntensity,
    lights: [{type, color, intensity, pos, target}],
    tasks: [{id, label, objectName}],
    objects: [{g, s, p, c, em, ei, rot, tr, op,
               name, interactable, promptText, interactionText,
               anim, screenType}]
  }

  5 roles: Doctor, Engineer, Chemist, Architect, Pilot
  Each has 8-10 interactable objects with detailed real-world descriptions.

  Object geometry types (field "g"):
    "box"    — BoxGeometry(s[0], s[1], s[2])
    "cyl"    — CylinderGeometry(s[0], s[1], s[2], s[3]||16)
    "sphere" — SphereGeometry(s[0], s[1]||16, s[2]||16)

  Optional object fields (additive, backward-compatible):
    anim: { type: 'spin'|'bob'|'pulse'|'swing'|'drip'|'flicker'|
                   'breathe'|'wobble'|'float'|'shimmer'|'glowPulse'|
                   'drift'|'elastic'|'rotate3d',
            speed: number, amplitude: number }
    screenType: 'heartrate'|'oscilloscope'|'radar'|'gauge'|'crt'|
               'equalizer'|'compass'|'map'|'code'

--- controls.js ---
  VRControls module. Handles:
  - Pointer lock mouse look (yaw/pitch with clamping)
  - WASD movement relative to camera direction
  - Sprint (Shift key, 1.8x multiplier)
  - Jump with simple gravity (Space key)
  - Bounding box wall collision (clamps position)
  - Pre-allocated THREE.Vector3 for _fw, _rt, _mv (no per-frame allocations)

  Tunable constants at top of file:
    SPEED=4, SPRINT=1.8, SENS=0.002, JUMPV=5, GRAV=12, PH=1.6, PR=0.3

--- interactions.js ---
  VRInteractions module. Handles:
  - Raycasts from screen center (THREE.Raycaster)
  - Detects interactable objects within IDIST=5 units
  - Highlights hovered object (changes emissive color/intensity)
  - Shows "E to interact" prompt (spring-animated via CSS)
  - Opens info panel with HTML content on E key
  - Calls VRTasks.complete() and VRSound.interact() on interaction
  - Stores original emissive values per-object for clean unhighlight

--- BloomPostFX.js ---
  Self-contained bloom post-processing. No EffectComposer dependency.
  Pipeline: camera render → threshold → Gaussian blur (h+v) → composite

  Uses WebGLRenderTarget (half-res for blur passes), ShaderMaterial,
  and a full-screen quad. 4 shader programs:
  - Threshold: extracts pixels above brightness threshold
  - Blur: 9-tap Gaussian (sigma ~2.0), separable h+v passes
  - Composite: additive blend of scene + bloom

  Constructor: BloomPostFX(renderer, scene, camera, {threshold, intensity, blurSize})
  Methods: render(), resize(w,h), dispose(), enabled property

--- Particles.js ---
  Lightweight THREE.Points-based particle system.
  3 presets: 'dust' (tiny motes), 'steam' (rising wisps), 'sparks' (bright dots)
  Particles driven by sine offsets for organic motion — no physics engine.
  Pre-allocated Float32Array for positions/velocities/lifetimes.

  Constructor: ParticleSystem(scene, {preset, count, bounds, origin})
  Methods: update(dt), dispose(), setVisible(bool)

--- CanvasTextures.js ---
  Manages live-updating CanvasTexture objects for in-world screens.
  5 screen types:
  - heartrate: ECG waveform with grid, heart icon, SpO2 text
  - oscilloscope: dual-channel waveforms (yellow sine + cyan square)
  - radar: rotating sweep line with blips, ring grid
  - crt: scanline effect, flickering status text
  - gauge: circular arc with needle, percentage readout

  Updates every 3rd frame for performance. Each texture is a canvas element
  drawn with 2D context, wrapped in THREE.CanvasTexture.

--- main.js ---
  Main entry point (~770 lines). Handles:
  - Quality auto-detection (GPU info via WEBGL_debug_renderer_info)
  - Three.js initialization with ACES tone mapping + PCFSoft shadows
  - BloomPostFX setup (high quality only)
  - Scene building from role data (walls, floor, ceiling, objects, lights)
  - Directional light for shadows (medium+ quality)
  - Fog per-role
  - Light shaft cones (additive-blended geometry)
  - Canvas texture assignment to screen objects (screenType field)
  - Animation system (reads anim field from objects):
    spin — rotates object around Y axis
    bob — sine-wave vertical oscillation
    pulse — emissive intensity oscillation
    swing — sine-wave Z rotation
    drip — position drops then resets (for IV drip)
    flicker — legacy emissive flicker
  - Dust particles in every room (medium+ quality)
  - Camera lerp (ease-out cubic) on role entry
  - Scene transition (fade-to-black overlay)
  - Sound-reactive lighting (lights pulse on interaction beeps)
  - Parallax tilt on role selection cards
  - Render loop: controls → interactions → camera lerp → animations →
    sound-reactive → particles → screen textures → bloom/render
  - Three.js loaded dynamically from CDN (with error fallback)

9. WHAT WAS BUILT (SESSION 5: MASTERPIECE UPGRADE)
================================================================================

Session 5 was a massive upgrade across ALL 9 files, adding dozens of new
features, animation types, post-processing effects, and HUD elements.

NEW FILES MODIFIED:
  All 9 files were rewritten or heavily upgraded.

--- controls.js — Enhanced Controls ---

NEW FEATURES:
  - Head Bob System: natural walking/sprinting motion with vertical bounce
    and lateral sway. Frequency and amplitude scale with sprint state.
    BOB_FREQ=8, BOB_AMP=0.04, BOB_LATERAL=0.02
  - Crouch System (C key): smooth camera height transition from 1.6m to 1.0m.
    Ease interpolation at 12x speed for smooth ducking motion.
  - Smooth Mouse Interpolation: target yaw/pitch values are interpolated
    toward actual values each frame (SMOOTH=0.15). Prevents jerky look.
  - Sprint Stamina: 100-point stamina pool. Drains at 25/sec while sprinting,
    regenerates at 15/sec when not sprinting. Must reach 20 to sprint again
    after exhaustion. Visual stamina bar in HUD.
  - Footstep Callback: VRControls.setOnFootstep(fn) hook. Called with
    'walk' or 'sprint' type on each head bob peak. Used by VRSound.
  - New getters: isSprinting(), isCrouching(), getStamina(), getStaminaMax(),
    isMoving(), getBobOffset(), getPitch()

TUNABLE CONSTANTS (at top of controls.js):
  SPEED=4.5, SPRINT=1.8, SENS=0.002, SMOOTH=0.15, JUMPV=5, GRAV=12,
  PH=1.6 (standing), CH=1.0 (crouching), PR=0.3,
  BOB_FREQ=8, BOB_AMP=0.04, BOB_LATERAL=0.02,
  STAMINA_MAX=100, STAMINA_DRAIN=25, STAMINA_REGEN=15, STAMINA_EXHAUST=20

--- BloomPostFX.js — Cinematic Post-Processing ---

NEW FEATURES (added to composite shader):
  - Film Grain: subtle noise overlay driven by hash function + time.
    Adds organic texture. Tunable via grain parameter (default 0.02).
  - Vignette: darkened edges drawing focus to center. Distance-based
    smoothstep falloff. Tunable via vignette parameter (default 0.35).
  - Chromatic Aberration: subtle RGB split at screen edges based on
    distance from center. Tunable via chromAb parameter (default 0.0012).
  - Exposure Control: adjustable tone mapping exposure (default 1.1).
  - Time-based grain: uses uTime uniform for animated grain pattern.

CONSTRUCTOR OPTIONS:
  BloomPostFX(renderer, scene, camera, {
    threshold: 0.55,    // bloom brightness threshold
    intensity: 0.65,    // bloom strength
    blurSize: 2,        // blur pass iterations
    grain: 0.02,        // film grain intensity
    vignette: 0.35,     // vignette strength

11. KNOWN ISSUES & FIXES APPLIED
================================================================================

ISSUE 1 (Session 1): Page stuck on loading after restructuring.
  CAUSE: controls.js and interactions.js referenced THREE at top level
         of their IIFEs (new THREE.Raycaster(), new THREE.Vector2()).
         Three.js loads async from CDN, so these executed before THREE existed.
  FIX: Moved all THREE references into init() functions, called from main.js
       after Three.js CDN script onload.

ISSUE 2 (Session 2): Page stuck on starting animation after visual overhaul.
  CAUSE: main.js line 228 had `new THREE.Vector3()` at top level of IIFE
         for cameraLerp state — same pattern as Issue 1.
  FIX: Changed cameraLerp to use null values initially, allocated THREE.Vector3
       objects inside initThree() after Three.js loads.

ISSUE 3 (Session 5): Page stuck on starting animation after Masterpiece upgrade.
  CAUSE: str_replace on roles.js Molecular Model object closed the outer
         object literal prematurely. The line:
           anim: { type: 'rotate3d', speed: 0.5, amplitude: 0 } },
         had an extra } which closed the parent object, pushing
         interactionText outside the object literal as a syntax error.
  FIX: Changed } }, to }, so the anim object closes but the parent stays open.

ISSUE 4 (Session 5): String.prototype.rpadStart is not a function (minor).
  CAUSE: CanvasTextures.js _drawCode function used rpadStart which doesn't
         exist in JavaScript. Should be padStart.
  FIX: Changed rpadStart to padStart. Only affects 'code' screen type
       which is not currently assigned to any object.

ISSUE 5 (Session 5): color-mix() CSS not supported in all browsers.
  CAUSE: style.css .role-card:hover used color-mix(in srgb, ...) which
         is a newer CSS function not supported in all browsers.
  FIX: Replaced with rgba(100,181,246,0.15) for broad compatibility.

GENERAL RULE FOR THIS PROJECT:
  NEVER reference THREE at the top level of any IIFE. Always defer to
  init() or constructor functions that are called after Three.js loads.
  NEVER use } }, to close an object with anim — always check that
  interactionText remains inside the object literal.

12. HOW TO ADD A NEW ROLE
================================================================================

1. Open roles.js
2. Copy any existing role object from the ROLES array
3. Change these required fields:
   - id: must be unique string (e.g., "chef")
   - title: display name (e.g., "Chef")
   - icon: emoji (e.g., "👨‍🍳")
   - description: short text
   - accentColor: hex color for UI accent (e.g., "#ff7043")
4. Define room:
   - roomSize: {width, height, depth} in world units
   - roomColor, floorColor, ceilingColor: hex colors
   - fogColor: hex color for scene fog (match room aesthetic)
   - playerStart: {x, y, z} — camera starting position
5. Define lights array (at least 1 ambient + 1-2 point lights)
6. Add interactable objects to objects[]:
   - At least 3 with interactable: true, name, promptText, interactionText
   - interactionText supports HTML (shown in info panel)
   - Optional: anim: {type, speed, amplitude} for animations
   - Optional: screenType: 'heartrate'|'oscilloscope'|'radar'|'gauge'|'crt'
7. Add matching tasks[] entries (objectName must match object's name)
8. The role card appears automatically on the selection screen

14. HOW TO ADD STL 3D MODELS
================================================================================

Three.js has an STLLoader (in examples/jsm/loaders/STLLoader.js).
To add STL models:

1. Include the STLLoader script (from CDN or local copy)
   <script src="https://cdn.jsdelivr.net/npm/three@0.128.0/examples/js/loaders/STLLoader.js"></script>
   (Note: use the examples/js/ version for non-module script tags)

2. In main.js, after the scene builds, load the STL:
   var loader = new THREE.STLLoader();
   loader.load('models/chair.stl', function(geometry) {
     var material = new THREE.MeshStandardMaterial({ color: 0x8B4513 });
     var mesh = new THREE.Mesh(geometry, material);
     mesh.position.set(x, y, z);
     mesh.scale.set(s, s, s);
     scene.add(mesh);
   });

3. STL files must be served from a web server (not file://) due to CORS.
   Run: python -m http.server 8000  (then open localhost:8000)

4. For per-role models, add a models[] field to role definitions
   and load them in buildScene().

--- ProceduralTextures.js — New File ---

Generates realistic textures at runtime without external files.
All textures are canvas-based (512x512) with noise, FBM, and procedural
patterns. Each texture type can produce diffuse, normal, and roughness maps.

10 texture types:
  wood — grain pattern with knots, grain lines, color variation
  concrete — multi-octave noise with aggregate pattern and stains
  tile — hospital/lab tile grid with grout lines, per-tile variation
  fabric — woven cross-hatch pattern with folds
  metalBrushed — horizontal brushed lines with color bands
  metalPolished — near-uniform chrome with subtle reflection hint
  noise — generic surface variation (FBM-based)
  linoleum — smooth surface with subtle marbling
  brick — offset brick pattern with mortar lines
  marble — vein pattern via distorted sine with color variation

Each generator produces canvas elements wrapped in THREE.CanvasTexture.
Textures are cached by type + options for reuse across objects.

Normal map generation:
  generateNormalFromDiffuse() — Sobel-filter-based normal extraction
  Reads luminance gradient of diffuse texture, outputs RGB normal map.
  Adjustable strength parameter for bump intensity.

Roughness map generation:
  generateRoughnessFromDiffuse() — luminance-to-roughness conversion
  Bright areas = smoother, dark areas = rougher.

--- SSAO.js — New File ---

Screen-space ambient occlusion for contact shadows where objects meet
surfaces. Self-contained, no EffectComposer dependency.

Pipeline: Render scene → Sample nearby depths → Calculate occlusion → Composite

Features:
  - 12-sample Poisson-disk-like kernel with time-based rotation
  - Distance-based occlusion calculation with bias
  - Edge-aware softening
  - Background early-out (depth > 0.98)
  - Adjustable radius and intensity

Constructor: SSAO(renderer, scene, camera, {radius, intensity, bias})
Methods: render(), resize(w,h), dispose(), setRadius(), setIntensity()

--- BloomPostFX.js — Color Grading Upgrade ---

NEW FEATURES added to composite shader:
  - Temperature shift (warm/cool tint) — adds orange to highlights,
    removes blue from shadows for warm cinematic look. Default: 0.05
  - Contrast adjustment — S-curve contrast boost centered at 0.5.
    Default: 1.12 (12% increase)
  - Saturation control — increases color vibrancy by mixing with luma.
    Default: 1.18 (18% increase)
  - Subtle S-curve — filmic tone response via cubic smoothstep.
    Adds slight highlight rolloff and shadow lift.

NEW UNIFORMS:
